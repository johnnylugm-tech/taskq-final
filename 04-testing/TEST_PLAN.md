# TEST_PLAN.md — taskq-api

> Generated by P4 Test Plan Author (runs once before per-FR testing).
> Source of truth: `01-requirements/SRS.md` (FR/NFR acceptance criteria) and `.methodology/quality_manifest.json` (FR list, NFR dimension mapping).
> Scope: covers every FR (FR-01 … FR-10) and every NFR (NFR-01 … NFR-12).
> Categories used per requirement: **P** (positive), **N** (negative), **B** (boundary), **E** (edge case).

## 0. Conventions

- Test IDs follow `TC-<FR|NFR>-<seq>` and map 1:1 to a single AC. Where a single test exercises multiple ACs of the same FR, the parent ID lists them (`TC-FR01-1 [AC-1.1, AC-1.2]`).
- Priorities: **P0** (gate-blocking / spec line directly cited), **P1** (gating dimension criterion), **P2** (supplementary).
- All integration tests are driven via `httpx.AsyncClient(transport=ASGITransport(app))` (NFR-10.2) — handler functions are never called directly.
- Migration tests (FR-07) use a real file-backed SQLite database (NFR-09.5); `pytest.skip` / `skipif` / `xfail` / zero-assert are forbidden (NFR-09.1, NFR-09.2, NFR-09.3).
